# Galantes Inventory Agent Scripts

This folder contains the script-first execution layer for the Galantes inventory publishing worker.

Rule: every Orca/n8n node must call a deterministic script command first. LLM/model calls are allowed only inside commands whose node contract has `llmAllowed=true`.

## Entrypoints

- Google Drive OAuth:

```bash
node scripts/inventory-agent/google-drive-oauth.mjs
```

- Node manifest:

```bash
node scripts/inventory-agent/nodes.mjs manifest
```

- Workflow status:

```bash
node scripts/inventory-agent/nodes.mjs status
node scripts/inventory-agent/nodes.mjs errors:use-cases
node scripts/inventory-agent/nodes.mjs n8n:export-workflow
```

## Token Control

- `llmAllowed=false`: no Gemini, OpenAI, Hermes, or Ollama call is permitted.
- `llmAllowed=true`: call local Ollama/Hermes first when possible, then Gemini/OpenAI only when the node requires vision, image editing, uncertain reasoning, or final copy QA.
- Price, cost, and stock are never generated by AI.
- Production writes require explicit user approval and Selenium Profile 9 evidence.

## Odoo Product DTO Safety

- Base DTO: `scripts/inventory-agent/odoo-product-template.dto.json`
- TypeScript DTO: `lib/odoo/product-template-dto.ts`
- Before enabling publication writes, run:

```bash
node scripts/inventory-agent/nodes.mjs odoo:fields-export
```

This reads `product.template.fields_get` from Odoo and writes
`data/inventory-agent/manifests/odoo-product-template-fields.json`.
Review `dtoCoverage.missingInDto` before allowing `odoo:publish`.

`odoo:dry-run` validates generated product payloads against the DTO write
allowlist, maps approved cost to Odoo `standard_price`, and keeps stock as
`approvedStock` instead of writing computed Odoo inventory fields such as
`qty_available`.

## Same-Product Image Matching

The ML matching layer is local and deterministic:

```bash
node scripts/inventory-agent/nodes.mjs ml:deps-check
node scripts/inventory-agent/nodes.mjs ml:index-status
node scripts/inventory-agent/nodes.mjs ml:build-index
node scripts/inventory-agent/nodes.mjs ml:cluster
node scripts/inventory-agent/nodes.mjs ml:contact-sheets
```

Outputs:

- `data/inventory-agent/manifests/processed-images.json`
- `data/inventory-agent/vectors/image-features.parquet`
- `data/inventory-agent/vectors/image-vectors.npy`
- `data/inventory-agent/vectors/image-neighbors.parquet`
- `data/inventory-agent/manifests/ml-product-clusters.json`
- `data/inventory-agent/review/*-contact-sheet.jpg`

The baseline vector uses deterministic local color/edge features plus
nearest-neighbor matching. It is intentionally script-first; CLIP/SigLIP or
FAISS can be added later behind the same commands without changing n8n.

`drive:scan` skips unchanged images that already have `featureStatus=ok` in
`processed-images.json`, using Drive file id plus checksum/modified time/size as
the processing signature. This keeps large folder runs incremental.

Large folders are batched with `INVENTORY_AGENT_MAX_QUEUE` (default `100`).
`drive-scan.json` reports `pendingTotal`, current `queued`, and `deferred` so
n8n can repeat the workflow without reprocessing completed images.

Review decisions:

- `SINGLE_IMAGE`: one photo becomes one product.
- `SAME_PRODUCT`: every image in the cluster belongs to the same product and
  must be uploaded to that product as primary image plus gallery.
- `REVIEW_MERGE_OR_SPLIT`, `UNCERTAIN`, `HUMAN_REVIEW`: blocked from publish.

`odoo:dry-run` maps approved image clusters as:

- `primaryImagePath`: first cluster image.
- `galleryImagePaths`: remaining cluster images.
- `allImagePaths`: complete source list for audit.

## Error Regression Registry

Known failures and their prevention rules are tracked in:

```bash
docs/inventory-agent-error-use-cases.md
```

n8n can read the registry with:

```bash
node scripts/inventory-agent/nodes.mjs errors:use-cases
```

When a new failure occurs, add it to the registry before continuing the
automation sequence.

## n8n Workflow Export

Safe intake/review workflow template:

```bash
node scripts/inventory-agent/nodes.mjs n8n:export-workflow
```

Output:

```text
data/inventory-agent/review/galantes-inventory-safe-intake-review.n8n.json
```

This workflow is inactive by default and does not publish to Odoo.

Post-review Sheet changes should run `review:sheet-export` before
`review:import`, so the local `review-queue.csv` always reflects the linked
Google Sheet before Odoo dry-run validation.
